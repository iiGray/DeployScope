# GPU Monitor

团队裸机 GPU 推理服务管理工具。推荐在管理机器上运行一个团队共享网页：浏览器独立填写部署草稿，共同查看和管理服务，服务器按提交顺序原子分配 GPU。每台 GPU 机器有自己的回环推理 API，调用必须发生在部署模型的那台机器上。

共享部署、登录口令、端口与迁移步骤见 [共享管理运行手册](docs/shared-console-runbook.md)。下面的本地体验仍兼容旧的个人客户端模式，不会自动启用团队登录或对外开放端口。

## 本地体验

需要 Node.js 20 或更高版本，无需安装 npm 依赖。

```sh
cd /Users/gray/Documents/Project/workspace/GPU_monitor
npm start
```

浏览器打开 http://127.0.0.1:5173，在右上角“连接设置”填写共享控制节点地址与管理密钥。只启动本地网页，不会自动连接演示中的机器。

界面演示：http://127.0.0.1:5173/?demo=1。演示状态仅存在浏览器中，与真实部署隔离。

控制台采用固定高度的紧凑工作台：桌面同时显示部署配置、vLLM 日志、显卡状态和服务列表；窄窗口用“部署 / 显卡 / 日志 / 服务”标签切换，不滚动整个页面，长日志和列表只在各自区域内滚动。刷新页面后默认读取当前机器运行中服务的 vLLM 日志，也可通过“日志服务”选择其他部署；日志读取失败不会把健康机器标记为离线。

开发联调（同机启动 Agent、控制节点、网页）：

```sh
npm run dev
```

首次生成 `.gpu-monitor/config.json` 私有配置，默认端口分别为 9000、8080、5173。默认所有服务只监听 `127.0.0.1`。当前 Mac 没有 NVIDIA GPU，会显示真实错误，不会显示虚假的显卡或启动结果。模型目录默认 `/models`，可在页面连接后修改为实际目录。

## 已接入功能

- 注册 / 连接 Agent；查询 `nvidia-smi` 的型号、利用率、显存、温度和进程占用，每 3 秒更新页面。
- 连接后默认浏览 `/data/hf_models`；点击文件夹逐级进入、返回或选择目录，模型路径下拉框仅列出所选目录的一级子文件夹，不必手动输入路径。新部署各自保存模型目录，不改变已有服务配置。
- 多 GPU 独占分配，按 GPU UUID 启动；拒绝被其他部署或外部计算进程占用的 GPU。
- 配置 vLLM 的上下文、显存比例和精度，一键启动部署。
- 在服务列表中修改、停止或重新启动部署。
- 已停止服务可经确认后删除部署记录并释放别名；不删除模型文件，历史配置与日志在服务器保留。
- 命令预览、实际子进程日志（最近 64 KiB）、API 地址复制；服务别名旁可复制推理请求的 `model` 字段。
- 全局服务别名唯一、部署配置持久化、管理 / 推理 / Agent 三种密钥分离。
- 每台服务器统一 `/v1/models`、`/v1/chat/completions`、`/v1/completions`，支持 SSE 流式响应；共享模式禁用控制节点跨机推理转发。
- 团队口令登录、各浏览器独立会话；同卡竞争先提交先占用，修改/停止/删除检查版本，网络失败显式重试原提交以避免重复启动。

详细配置与裸机启动见 [部署说明](docs/deployment.md)。无需浏览器 SSH 连接：网页经控制节点调用各机 Agent。共享模式下用户使用网页口令，不需要控制节点管理密钥；所有登录用户有相同管理权限。

使用系统字体，无外部字体或前端依赖。

## 验证

```sh
npm test
npm run check
```

测试通过真实 HTTP 服务与独立测试子进程验证，GPU 遥测由测试夹具注入，不代表已在真实显卡上完成 vLLM 验证。生产路径没有模拟 GPU 回退。

入口：`server.mjs`（本地客户端）、`backend/cli.mjs`（Agent / 控制节点）；不需要 npm 安装，GPU 机器需要另行准备 NVIDIA 驱动与可用的 vLLM 环境。

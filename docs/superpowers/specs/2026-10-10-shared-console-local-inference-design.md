# DeployScope：多人共享管理网页与服务器本机推理

日期：2026-10-10（Asia/Shanghai）

状态：总体方案已获用户确认；本设计文档待用户审阅，尚未实施。

## 1. 目标与范围

将现有裸机部署工具改为团队共用的管理网页。用户无需在自己的电脑上运行网页服务或建立 SSH 隧道，即可访问 6kd_7 上的统一管理入口。每个人的未提交操作彼此独立，所有人看到同一份机器、GPU、部署服务和部署日志。

GPU 分配采用先到先占：服务器先接受的有效提交优先，后续冲突提交被拒绝，不抢占、不自动等待空闲资源。所有团队成员继续拥有同等管理权限，可管理共同的服务。

推理与共享管理分开：部署在哪台机器，推理调用就发生在哪台机器。6kd_6 与 6kd_7 都提供自己的 `http://127.0.0.1:18080/v1`，每个入口只认识该机器上的部署。相同 URL 不代表同一个服务；`127.0.0.1` 始终是调用程序所在主机。

不包含公网匿名管理、角色体系、逐用户 GPU 配额、资源等待队列、多控制节点高可用、跨机推理、自动安装 vLLM 或下载模型。

## 2. 当前实现与迁移约束

2026-10-10 只读核对结果：

- 6kd_7：网页监听 `127.0.0.1:15173`，Controller 监听 `127.0.0.1:18080`，Agent 监听 `127.0.0.1:19000`。Controller 目前把所有注册机器的模型合并成一个推理入口。
- 6kd_6：只有 Agent，监听 `10.100.11.6:19000`，没有本机推理网关。
- Mac 上现有 SSH 隧道同时转发网页 15173 和推理 18080；这会让 Mac 的回环地址实际连接到 6kd_7，不符合新的调用约定。
- Controller 与 Agent 已有串行操作队列、状态持久化、独占 GPU 检查、外部计算进程检查和单实例锁。
- 网页目前仅允许回环 Host/Origin，并通过服务端保存的管理密钥代理请求。单纯放开监听地址不构成可安全使用的多人版本。
- 6kd_7 的两条已保存部署在核对时均为 stopped、PID 为空；6kd_6 暂无托管部署。部署前必须重新核对，不能依赖此历史状态。
- 6kd_6 尚未确认可用的 vLLM 可执行环境。增加网关不等于模型已可启动；这项限制必须在交付时明确报告。

保留所有已有模型文件、部署 ID、服务别名、GPU 物理身份、日志和停止态记录。保留目录选择器、别名复制、停止态删除确认、紧凑排版等现有行为。

## 3. 组件边界与端口

采用每台 Agent 附带独立本机推理网关的对称结构，而不是让 6kd_6 的推理经过 6kd_7。

| 组件 | 6kd_7 | 6kd_6 | 可访问范围 |
| --- | --- | --- | --- |
| 共享网页和管理代理 | 管理网络地址的 15173 | 不运行 | 能连通管理网络/VPN、持有网页访问口令的成员 |
| Controller | `127.0.0.1:18081` | 不运行 | 6kd_7 的网页代理 |
| Agent 管理接口 | `127.0.0.1:19000` | `10.100.11.6:19000` | 本机或获准的 Controller |
| 本机推理网关 | `127.0.0.1:18080` | `127.0.0.1:18080` | 对应服务器上的调用程序 |
| 各 vLLM 实例 | 本机回环动态端口 | 本机回环动态端口 | 对应本机网关 |

Controller 从 18080 移到 18081，释放两台机器一致的本机推理端口。同步更新私有 Console 配置，不能继续读取指向旧 Controller 端口的 console.json。

候选团队入口为 `http://174.1.59.7:15173`，与用户当前可通过 VPN 到达的 6kd_7 管理地址一致。部署必须核实该路径的可信网络边界；地址不是 RFC1918 并不能证明它是安全内网。只有确认处于团队管理网络/VPN，或提供有效 HTTPS 保护后，才能传输访问口令。不能确认网络保护时不裸露管理端口，报告具体连通性限制。

网页绑定具体管理地址而非全部接口。需要防火墙调整时只增加该服务端口的明确规则，不修改无关规则或放宽 Agent 管理入口。最终交付的是从用户电脑实际验证过的非回环 URL，不将候选地址宣称为已上线。

保留 15173-only SSH 网页兼容通道，其远端目标同步改为 `174.1.59.7:15173`，并显式允许该兼容入口的 localhost/127.0.0.1 Host 与 Origin。兼容入口也必须登录。移除我们创建的 Mac 18080 推理转发，不删除其他用户或 Codex 的 SSH 连接。

## 4. 多人访问与鉴权

共享模式显式启用；原有仅本地 Console 模式保持兼容。共享模式必须配置独立、随机的网页访问口令，不能复用 Controller 管理密钥、Agent 密钥或推理密钥。

所有成员用同一团队口令登录，但每个浏览器建立独立随机会话。会话使用 HttpOnly、SameSite=Strict Cookie，HTTPS 下增加 Secure，最长有效期 12 小时，退出即失效。登录请求限制大小和尝试频率，错误响应不泄露口令、内部密钥或文件路径。

只允许登录页、登录所需静态资源和登录接口在未认证时访问；读取共同状态、浏览目录、读取日志及全部管理操作都要求有效会话。返回的状态不包含任何管理或推理密钥。访问口令保存为不可还原的校验值，原始生成口令通过受限的交付文件提供，不放进 URL、Git、截图或普通日志。

明确配置可信 Host 与 Origin，拒绝任意 Host。写请求继续要求同源 Origin 和专用请求头；不使用任意传入 Host 或未经信任的转发头来决定可信来源。通过反向代理启用 HTTPS 时仅信任明确配置的代理及外部 Origin。

共享模式中 Controller 地址和代理管理密钥只由服务器配置决定；网页不允许成员修改这份全局连接配置。添加/更新机器仍是认证后的共同管理操作，Agent 密钥仅提交到服务器，不回显或保存在浏览器持久化存储中。

全员管理权限意味着其他成员可以停止、修改或删除共同服务；“独立操作”仅指未提交的浏览器状态独立，不是服务私有或所有者独占。

## 5. 浏览器私有状态与共同状态

私有状态：选择的机器、是否连接、浏览目录、模型选择、GPU 勾选、参数草稿、正在编辑的服务、选中的日志、弹窗、错误提示。保持在当前浏览器页面中，不上传成全局草稿。另一位成员连接机器或切换目录不会改变这些内容。

共同状态：已注册机器、实时 GPU 使用与占用归属、已提交部署、部署配置版本、提交序号、运行状态及对应服务的部署日志。以 Controller/Agent 为事实来源，沿用约 3 秒的轮询刷新；界面显示可能稍晚于服务端占用决定，不承诺所有浏览器瞬间同步。轮询更新保留当前表单内容，不把别人的部署写进自己的未提交草稿。

GPU 勾选不占用资源。共享状态更新后，可提示草稿中的卡已被占用；最终决定仍由服务端做出，不能只依赖前端灰掉按钮。

共享模式的连接设置改为只读连接信息、退出入口和认证后的机器管理，不允许全局代理被单个浏览器重新配置。页脚标注团队共享管理，避免继续显示“本地客户端”。

## 6. 提交顺序与资源锁定

“先来后到”定义为：请求通过鉴权、完整收到 JSON 并通过基本格式校验后，进入 Controller 写操作队列的顺序。不给浏览器本地时间或点击时间排序，避免网络延迟和时钟差异。排队有请求体大小和接收超时限制，不允许不完整请求无限阻塞。

Controller 分配单调递增、持久化的提交序号。资源变更必须经单一 Controller 和目标 Agent 的串行队列；单实例锁防止同一状态目录运行第二个调度实例。轮询和后台异步检查不能绕过写操作保护。

目标 Agent 在同一串行操作内重新检查模型路径、全部目标 GPU、托管保留状态及外部计算进程。全部通过后，先持久化 starting 状态和整组 GPU 保留，再启动 vLLM。多卡请求全有或全无，不先占一部分再发现另一张不可用。

同一 GPU 的后续冲突请求返回 409 并指出已占用的资源；不会停止先提交的服务，也不会创建等待释放后自动启动的隐藏任务。不同机器上的 GPU 是不同资源。

启动中的服务继续占用资源。只有确认进程/进程组退出后才释放；断网、浏览器关闭、请求超时或未知进程身份不释放。外部管理员绕过工具直接启动进程不受工具锁强制约束，但 Agent 必须检测并拒绝已发现的外部占用，不终止外部进程。

新建和状态变更请求使用稳定 requestId；一次用户提交的网络重试复用同一个 ID。服务端持久化操作身份和结果，同 ID、同载荷不重复部署，同 ID、不同载荷返回 409。已确认记录保留 7 天且最多 10000 条；未确认记录独立保留，不参与按时间或数量的裁剪。超过保留范围的提交不保证幂等，客户端不得把旧请求当成新部署静默重放。

## 7. 同一服务的并发修改

每条部署增加独立配置/操作 revision，旧记录初始化为 1。共享模式中更新、启动、停止和删除必须使用 expectedRevision，缺少版本的旧客户端提交被拒绝；原有本地兼容模式保留既有接口行为。健康检查、GPU 读数刷新不增加 revision。

在产生副作用之前校验版本。第一个有效修改接受后，后来的旧版本操作返回 409，提示服务已变化、需要刷新后重新确认，不自动覆盖或自动重试新版本。幂等重试先匹配 requestId，再做版本判断，避免自己的已成功操作被误判为别人的冲突。

结果未知时保留 pending 标记和已接受的操作身份，不能允许不同配置继续覆盖。已确认未产生副作用的校验错误不消耗版本；已接受或结果未知的操作占用新版本。保留现有 unknown/orphaned/deletePending 的保护行为。

停止态删除仍需显式确认；确认框绑定 ID、别名和当前 revision。确认期间状态变为运行中或版本变化时，后端拒绝旧删除，而不是删除刚被别人启动的服务。

## 8. 服务器本机推理

新增独立本机推理组件，使用同一 AgentManager 的状态，不复制全局 Controller 状态，不接受远程 Agent 地址作为推理目标。

只监听固定 `127.0.0.1`，提供 `/v1/models`、`/v1/chat/completions`、`/v1/completions` 和健康检查。鉴权使用该机器独立的推理密钥，不接受网页会话或管理密钥。模型列表只包含该机器上就绪的部署；别名不存在或属于其他机器时返回 404，不跨机寻找或回退。

网关直接流式转发到自己机器上 vLLM 的回环动态端口，使用实例私有密钥。沿用现有超时、断开取消、SSE 和错误处理，不串行化不同推理请求。

Controller 的跨机推理路由及 Agent 管理端口上的 inference 路由在新模式中禁用，避免共享网页或 6kd_7 用管理密钥代理调用 6kd_6 模型。旧模式兼容配置不得在生产新模式中意外启用跨机推理。

网页每条服务显示并可复制“本机推理 API：127.0.0.1:18080/v1（在 6kd_6/6kd_7 上调用）”，与别名复制按钮配合使用。不再将一个含糊的全局 API 标注到所有机器的服务上。网页管理地址与推理地址清楚区分。

回环监听不会阻止有系统管理权限的人自行创建 SSH 隧道；工具保证默认监听、路由和交付配置符合本机调用，不承诺对管理员实施无法绕过的网络隔离。

## 9. 运行、迁移与回滚

实施前对两台服务器的源代码、私有配置、Agent/Controller 状态及服务单元建立带时间戳、权限受限的备份。保留现有未提交修改，不通过覆盖工作区或 Git reset 实施。

分别验证 Node 运行时、端口空闲、目标地址存在和网络访问路径。只更新本项目服务；6kd_6 现有 9000 服务及其他 GPU 作业不属于迁移范围。

重启前重新检查全部托管服务是否确认为 stopped、PID/进程组为空，并检查 pending/unknown/orphaned 操作。若有正在运行的服务，先报告影响并等用户明确允许中断；不因部署网页而静默停止模型。

6kd_7 私有配置迁移 Controller 到 18081，更新共享 Console、会话配置及本机网关。6kd_6 私有配置增加本机网关，保留既有 Agent 访问限制。网关与 Agent 生命周期一致，启动失败不留不完整监听或失去锁的后台服务。

调整我们自己的 Mac 隧道时只移除 18080 转发，保留网页 15173 兼容入口。生产的非回环网页入口验证通过后才交付，失败则恢复本项目先前配置/源码/单元，不能盲目恢复覆盖期间新产生的部署状态。

## 10. 验收与交付证据

- 原有完整测试通过；补充共享 Console、鉴权、Host/Origin、会话过期/退出、凭据不泄露及固定连接配置的测试。
- 两个独立浏览器会话看到相同服务，但连接机器、目录浏览、GPU 勾选和编辑草稿互不影响。
- 通过 HTTP 端到端并发提交同一卡，先入队的有效请求获得资源、后者 409；多卡冲突不留下部分占用；不同机器相同 GPU 编号不冲突。
- 启动期间继续保留 GPU；失败且进程退出后释放；网络超时和身份未知时不误释放。重试 requestId 不生成重复部署，进程重启后规则保持。
- 两个客户端修改同一 revision，只有第一份有效配置生效；旧停止/启动/删除不产生副作用；停止态删除确认和 pending 保护无回归。
- 用 CPU 假推理进程验证两台独立网关的模型列表、别名隔离、密钥隔离、流式响应及并发。不给生产 GPU 运行额外模型，不停止任何外部任务。
- 服务器端检查各自 `127.0.0.1:18080/health` 和认证后的 `/v1/models`；从管理网络访问推理端口失败；旧跨机 inference 路由被拒绝。健康检查通过不等于真实模型已加载。
- 从用户电脑的非回环地址验证登录和共同状态；确认未登录无法读状态或提交。真实网页检查保持紧凑布局，不引入整体页面滚动。
- 交付实际验证过的网页 URL、访问口令取用方式、每台机器管理/推理端口、测试结果以及剩余运行环境限制。此设计文档本身不是上线或功能完成的证据。

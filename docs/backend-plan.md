# 后台实现计划

目标：沿用已确认的精简单页，让多个本地客户端通过一个控制节点管理裸机上的 vLLM 部署，并使用统一 API 调用。

## 接口与边界

- 本地网页：静态服务只监听回环地址；代理共享控制节点请求，管理凭据存储在本地服务的私有配置文件。
- 控制节点：维护机器注册、全局模型别名、部署记录与 API Key；所有管理操作串行化并持久化。转发 OpenAI 格式的聊天/补全与流式响应。
- Agent：读取 nvidia-smi，扫描本机模型目录，按 GPU UUID 启动 vLLM；GPU 独占，拒绝已被外部进程使用的卡。使用进程组停止任务，只处理经过身份验证的自有进程。
- vLLM：仅监听 Agent 的回环地址，由 Agent 转发推理请求；参数通过 argv 传递，不运行用户输入的 shell。

## 实现顺序

1. 遥测解析、参数校验、私有持久化与 HTTP 工具；用 NVIDIA 命令样本验证单位转换和外部进程占用。
2. Agent 生命周期、模型扫描、日志和进程组；用独立测试推理进程验证 GPU 锁、并发抢占、停止、错误与状态恢复。
3. 控制节点与网关；验证鉴权、机器凭据不暴露、别名唯一、故障状态、SSE 首个分片即时转发。
4. 本地代理与页面真实模式；演示模式显式保留，真实模式失败不回退到假数据。轮询不打断输入。
5. 启动脚本、Linux systemd 模板、使用文档；全套测试和浏览器连接检查。

## 验收重点

- 多个用户同时选同一张 GPU，只有一个部署被接受。
- 不停止用户原先手工运行的 GPU 进程。
- 停止尚未完成时不释放 GPU；身份不明的残留进程保持占用。
- 控制节点/Agent 离线时显示真实故障，不显示虚假的就绪状态。
- 所有网络服务默认绑定回环地址，远端监听由部署配置明确启用。
- 只支持同一机器内修改部署；跨机器迁移以停止旧部署并新建实现。
- 真实 NVIDIA/vLLM 验证需要远端 GPU；本地集成测试替身与真实运行结果必须分别报告。

## 实现记录

- 遥测 / Agent / 控制节点 / 本地代理 / 页面真实模式 / 启动配置 / systemd 模板均已实现。
- 浏览器验证：连接，GPU 展示，创建，修改 GPU 并重启，停止，再启动，日志读取，连接设置保存，以及轮询保留输入草稿。
- 真实模式在当前 Mac 显示 `nvidia-smi` 不可用；测试进程与模拟 GPU 只位于测试夹具，未宣称硬件验证完成。
- 独立审查的重要问题均补充 RED→GREEN 回归：失效子进程身份、GPU 编号重排、超时后的别名锁、真实路径归一化、无关离线节点影响推理、日志错误误报集群离线。
- 额外验证：重启 Boot ID 检查、每次强制停止前重新核验身份、幂等修改操作 ID，以及上游未返回头时的推理截止时间。
- 当前全套 35 个自动化测试通过，全部 JavaScript 语法检查通过。
- 边界：直接修改 Agent / 多控制节点管理同一机器不支持；长期日志轮转、真实 vLLM worker 行为及 CUDA 分配仍需实际 GPU 环境验证。
